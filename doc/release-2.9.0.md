# Venera Prime 2.9.0

> 基于上游 2.8.1（`v2.8.1`），合并本地长期补丁后发布。fork 发布标签统一使用 `m` 前缀（本次为 `m2.9.0`）。

## 本次更新

- 恢复本地下载：新增「接管旧下载目录」入口。选择旧版本的下载目录后，该目录直接成为本地存储路径，不复制、不删除任何文件；相对条目自动跟随新根，只存在于旧根的条目改为绝对路径并标记为非应用管理（可读、不会被应用删除）。新旧根都存在同名目录时进入「重复副本」页，可删除或重命名为 `原名 (old copy)`；旧路径之外或仍被库引用的目录一律拒绝操作。
- 存储目录迁移：设置里的「Set New Storage Path」按目录状态分流。空目录沿用原流程——复制完成后提交路径，再清理旧目录；提交后若旧目录被占用则保留文件并记录日志，绝不回指半删目录。复制失败会清理未完成的副本，避免后续接管把半份数据当成完整副本。非空目录改走原地接管，并同样列出重复副本。两个方向的嵌套路径（新目录在旧目录内、新目录包含旧目录）都会被拒绝。
- 本地漫画元信息：`language` 与 `page_count` 写入本地库，旧库通过增量列迁移自动升级；首次打开本地库时按 `metadata.json` / `ComicInfo.xml` 与磁盘文件回填一次。列表新增信息行（作者、语言、章节数、页数），体积与来源仍由原有页脚显示，虚拟分类、排序、批量移动保持不变。
- 归档与阅读修正：压缩包解压增加字节上限、流式 CRC 与 7z 边界校验；搜索分页恢复改为确定性重放；阅读器页码映射做钳制，瀑布流错误提示软化。
- 平台与发布：iOS/macOS 接管目录时保存安全作用域书签并在启动时恢复访问；发布工作流只接受 `mX.Y.Z` 形式的标签。

## 请更新后验证并反馈

- 旧版本升上来后首次打开本地库：列表信息行是否补齐语言与页数；原分类、排序、批量移动是否照旧。
- 用「接管旧下载目录」指向老下载目录：库中漫画是否可直接打开、旧目录文件是否原样保留；出现重复副本时三种操作（删除 / 改名 / 暂不处理）是否符合预期。
- 设置里切换存储路径：空目录应复制后切换，非空目录应原地接管；切换后重启应用路径是否保持。
- iOS/macOS：接管后重启应用，目录是否仍可读写。

## 验证范围

- `flutter analyze --no-pub`：无问题。
- 定向回归：本地库、导入/接管、存储迁移、压缩包、列表性能等共 55 项通过（1 项按平台跳过）；其中 `import_comic_restore_test`（7 项）、`local_storage_migration_test`（4 项）、`local_path_access_retention_test`（2 项）为本次新增。
- Windows 全量 `flutter test`：386 通过 / 17 跳过 / 25 失败。失败均为基线环境类（临时目录竞争、`zip_flutter` 原生库缺失、平台通道、原生解码），其中 `search_history_test` 为临时目录竞争偶发，单独复跑通过，失败集合未扩大。
- 发布工具：`tool/test_release_identity.py` 6 项通过（改用 `sys.executable`，Windows 下不再因 `python3` 缺失报错）；`tool/test_alt_store.py` 3 项通过；`tool/check_version.py` 2.9.0+290 通过。
- Android SAF：涉及 SAF 的改动需真机验证，并按 AGENTS.md 预构建后以 `aapt dump badging` 核实包名。
- iOS/macOS：书签持久化与启动恢复需真机确认重启后仍可读写；Dart 侧保留标志已有单测覆盖。
- 已知限制：Windows 完整构建仍被 `rhttp` 的 `ring v0.17.14` C 编译阻断，端到端验证依赖单元测试；该问题单独立项处理。
