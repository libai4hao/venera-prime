# Venera Prime 入门指南

面向第一次改这个仓库的人（和 agent）。目标：15 分钟跑起来，然后知道「想改 X 该动哪几个文件」。

本文所有 `路径:行` 基于 `04ff270`（v2.6.3）。行号会漂，符号名不会——对不上就按名字搜。

---

## 1. 这是一个什么形状的项目

Flutter 单体桌面/移动应用：漫画阅读器。Android / iOS / Windows / macOS / Linux 五端同一套 Dart 代码。

两个容易误判的地方，先说清楚：

**① 它不是插件式架构。** 没有依赖注入，没有 Provider / Bloc / Riverpod / get_it。全局状态就是模块级单例，`App`、`appdata`、`ComicSourceManager()`、`JsEngine()` 直接 import 就能用。你要的上下文几乎总在这几个里。

**② 漫画源的抓取逻辑不是 Dart 写的。** 每个站点是一个 `.js` 文件，跑在嵌入式 QuickJS 里（fork 的 `flutter_qjs`）。Dart 侧只做两件事：把 JS 函数包成 Dart 回调、解析它吐回的 `Map`。所以「某站点抓不到图」这类问题，第一现场是 JS 脚本（`${dataPath}/comic_source/*.js`），不是 `lib/`。

规模参照：`lib/` 173 个文件，`test/` 84 个（+ `test/support/` 10 个共享用例表），`integration_test/` 13 个，`doc/` 38 篇。

## 2. 15 分钟跑起来

### 2.1 版本必须对上，别升

| 工具 | 版本 | 钉在哪 |
| --- | --- | --- |
| Flutter | 3.41.4 | `.fvmrc`、`pubspec.yaml:9` |
| Dart | >= 3.8.0 | `pubspec.yaml:8` |
| Rust | 1.85.1 | `rust-toolchain.toml` |

Rust 是个坑：`git ls-files '*.rs'` 是空的，仓库里一行 Rust 源码都没有。但 `rhttp`（`pubspec.yaml:61`）等依赖在构建期要编译 Rust，所以 `flutter build` 需要 rustup 就位（CI 用 `rustup show` 校验，`.github/workflows/main.yml:111`、`:222`）。`flutter test` 不需要 Rust。

用 FVM 的话 `fvm flutter ...` 替换下面所有 `flutter` 即可。

### 2.2 三条命令

```sh
flutter pub get
flutter analyze --no-pub      # 唯一的静态检查（flutter_lints ^5.0.0）
flutter test --no-pub         # 全量 94 个 test/*.dart
```

跑单个：`flutter test --no-pub test/reader_spread_test.dart`。

### 2.3 第一件要记住的事：CI 不跑测试

`.github/workflows/main.yml` 是唯一的 workflow，396 行，里面**没有** `flutter analyze`，也**没有** `flutter test`。它只做：`python3 tool/check_version.py` 查版本一致性 → 各平台 `flutter build` → 发 Release。

也就是说：CI 全绿 == 五个平台能编译，仅此而已。测试和 lint 只有你本地跑。别把 CI 绿灯当成验证通过。

### 2.4 真机跑起来

```sh
flutter run -d windows      # 桌面调试最快
flutter run -d chrome      # 不推荐：WebView / 文件系统相关功能在这里表现不准
```

启动失败先看 `lib/foundation/log.dart` 落的日志文件，再看主界面是否显示重试页（那条路径见下面「启动」一节，它刻意不崩）。

### 2.5 打包（CI 用的不是裸 flutter build）

| 平台 | 实际入口 |
| --- | --- |
| Windows | `python windows/build.py`（`.github/workflows/main.yml:256-258`） |
| Linux | `python3 debian/build.py x64` → `dart run flutter_to_arch` → `bash tool/build_appimage.sh x86_64`（`:276-291`） |
| Android | `flutter build apk --release`，需 `android/release.keystore` + `android/key.properties`（`:194-229`） |
| macOS / iOS | `flutter build macos --release` / `flutter build ios --release --no-codesign`（`:116`、`:154`） |

`windows/build.py`、`debian/build.py`、`tool/build_appimage.sh` 里做的事不止 `flutter build`（还要拷贝资源、改元信息），所以手动发版别绕过它们。

## 4. 一条真实调用链：阅读器加载一章的图片

想理解「Dart 怎么调到 JS」，跟这一条最省事。全部已读码验证。

```
lib/pages/reader/images.dart:77
  reader.type.comicSource!.loadComicPages!(reader.widget.cid, cp)
        │
        │  这个字段的类型是 LoadComicPagesFunc?（lib/foundation/comic_source/comic_source.dart:315）
        │  它在解析源脚本时被绑上一个闭包：
        ▼
lib/foundation/comic_source/parser.dart:847-859  _parseLoadComicPagesFunc()
  var res = await JsEngine().runCode("""
      ComicSource.sources.$_registryKey.comic.loadEp(${jsonEncode(id)}, ${jsonEncode(ep)})
  """);
  return Res(List.from(res["images"]));
        │
        ▼
lib/foundation/js_engine.dart:300  runCode(String js, [String? name])
  在 QuickJS 里求值；JS 里调用的网络请求由 Dart 侧代发：
lib/foundation/js_engine.dart:238  _http(Map<String, dynamic> req)
        │
        ▼
  返回 Res<List<String>>（图片 URL 列表）
        │
        ▼
lib/pages/reader/images.dart:81-100
  res.error ? 显示错误 : (reader.images = res.data → resolveChapterNavigation() → updateHistory())
```

从这条链能读出四条规律，后面会反复用到：

1. **每个 JS 能力都有一个 `_parseXxxFunc()` 对应。** 要加新能力，在 `parser.dart` 里加一个 `_parseXxxFunc()`，加进 `ComicSource` 的构造（`comic_source.dart:528` 附近），再在模型里声明字段（`:315` 那一带的 `final LoadXxxFunc? xxx`）。
2. **源在 JS 侧按 `ComicSource.sources.<registryKey>` 寻址。** `_registryKey` 是源的身份，不是源名。
3. **函数返回值统一是 `Res<T>`。** 成功 `Res(data)`，失败 `Res.error(msg)`。JS 抛异常在 Dart 侧被 catch 成 `Res.error` 并 `Log.error("Network", ...)`。所以「源报错」和「代码 bug」在 UI 上是同一种表现，排错要看日志。
4. **页面只按 `res.error` 分支**，不重试。重试逻辑在 `parser.dart:870` 的 `retryZone`（登录态相关），不在 UI。

阅读器自身拆成 8 个文件（都在 `lib/pages/reader/`）：`reader.dart`（主 State 与生命周期）、`images.dart`（1712 行，取图 + 主逻辑）、`chapters.dart`、`gesture.dart`、`comic_image.dart`、`loading.dart`、`scaffold.dart`、`chapter_comments.dart`。改翻页/缩放看 `gesture.dart`，改图片加载看 `images.dart`。

## 5. 启动与数据

### 5.1 启动顺序（有序，不要插队）

```
lib/main.dart:21            main()
  ├─ :22-25  --headless 参数 → lib/headless.dart:17 runHeadlessMode() 接管
  ├─ :26     runWebViewTitleBarWidget() 提前 return
  ├─ :27-28  overrideIO() + runZonedGuarded
  └─ :31     lib/init.dart:54 init()
               ├─ lib/foundation/app.dart:88  App.init()      落 dataPath / cachePath
               ├─ lib/foundation/app.dart:97-106  App.initComponents()
               │    appdata → history → favorites → local → readLater → readingStatistics
               │    逐个 await，前一个成功才到下一个
               ├─ 翻译 / OpenCC / 后台任务 / CacheMaintenanceService
               └─ lib/init.dart:105-112  unawaited(漫画源初始化)   ← 故意不 await
lib/main.dart:32            runApp(MyApp)
```

两条规则：

- **核心存储失败必须 `return InitializationFailure(...)`**，不要裸抛。那样主界面会渲染重试页，且**不动用户已有数据**（`lib/main.dart:219-232`、`:366`）。这块的承诺是"初始化失败不能让用户丢书"。
- **非核心失败 `Log.error` 吞掉继续**（`lib/init.dart:66-93`）。漫画源初始化不 await，所以启动不会被某个源卡死，UI 里要处理"源还没加载"的状态。

### 5.2 存储地图：两条路，别混

**设置 / 偏好 → `appdata.settings['key']`**

落到单个 `appdata.json`（另有 `syncdata.json` 参与 WebDAV 同步）。写盘统一走 `appdata.saveData()`——原子写 + 串行化 + 触发同步（`lib/foundation/appdata.dart:80-111`）。

读入时按 key 做类型校验（`lib/foundation/appdata.dart:25-78`）：类型不符、嵌套深度 > 8、字符串 > 1MB、列表 > 10000 项，**该值直接丢弃并打 warning**。

> 加新设置项的隐形陷阱：旧版本写进去的值必须能通过新版本的校验。改了某个 key 的类型（比如 int → String），老用户升级后这一项会静默复原成默认值，不留痕迹只有日志里的 warning。要兼容就换 key 名或写迁移。

**结构化业务数据 → 每域一个 SQLite 库**

用 `package:sqlite3` 直接 `sqlite3.open`，没有 ORM、没有 codegen：

| 域 | 打开位置 |
| --- | --- |
| history | `lib/foundation/history.dart:239` |
| favorites | `lib/foundation/favorites.dart:329` |
| local | `lib/foundation/local.dart:336` |
| read_later | `lib/foundation/read_later.dart:101` |
| reading_statistics | `lib/foundation/reading_statistics.dart:92` |
| cookie | `lib/network/cookie_jar.dart:20` |
| cache | `lib/foundation/cache_manager.dart:65` |

加表加到对应域里，不要为单个新功能再开一个库文件——每开一个库就多一份备份/迁移/同步的面。

### 5.3 全局单例速查

| 单例 | 位置 | 用来干什么 |
| --- | --- | --- |
| `App` | `lib/foundation/app.dart:127-128` | 路径、`rootNavigatorKey`、五个数据管理器、`forceRebuild()` |
| `appdata` | `lib/foundation/appdata.dart` | 设置读写 |
| `ComicSourceManager()` | `lib/foundation/comic_source/comic_source.dart:40-44` | 工厂单例，管理所有源 |
| `JsEngine()` | `lib/foundation/js_engine.dart` | 跑 JS，`runCode` / `resetDio` / `dispose` |

`App` 是 `final App = _App()`，故意大写首字母，靠 `// ignore: non_constant_identifier_names` 压住 lint。别为了干净改成 `app`——全仓库都在用 `App.`。

新增长生命周期服务：`with Init` mixin，实现 `doInit()`，外部只调 `ensureInit()`。它幂等、失败会重置以便重试（`lib/utils/init.dart:6-31`）。自己写 `if (_inited) return` 会漏掉并发首次调用。

## 6. 陷阱清单

按踩到的概率排序。

1. **CI 绿灯不等于测试通过**（§2.3）。本地跑 `analyze` + `test`。
2. **`comic_source.dart` 的 5 个 part 文件不能有自己的 import**。`category` / `favorites` / `parser` / `models` / `types`（`lib/foundation/comic_source/comic_source.dart:27-35`）只能用主文件的 import。想在 `parser.dart` 里加一个新包，import 加在主文件。新增 part 文件要同步加 `part` 指令。
3. **改 `appdata` 里已有 key 的类型 = 老用户静默丢设置**（§5.2）。
4. **初始化里裸抛会让用户看到故障页**，正确姿势是 `return InitializationFailure(...)` 走可重试路径（§5.1）。
5. **界面文案不是 ARB 也不是 codegen**。源码里直接写中文/英文，展示处加 `.tl`，运行时查 `assets/translation.json`（`lib/utils/translations.dart:17`）。所以：`Text("阅读记录".tl)`。翻译文件缺条目不会编译失败，只是界面上不翻译——加文案时顺手补 json。
6. **导航别用裸 `Navigator.push`**。用 `context.to(() => X())` / `context.toReplacement(...)`（`lib/foundation/context.dart:17-25`），底层 `AppPageRoute` 带转场和返回键行为。同一个文件还提供 `width` / `height` / `padding` / `colorScheme` / `isDarkMode` / `showMessage`，先翻它再翻 Flutter 文档。
7. **`print` 不会报错但没人这么写**。`avoid_print` 在 `analysis_options.yaml:26` 被关掉了；项目一律 `Log.error/warning/info`（`lib/foundation/log.dart:90-104`）。初始化前打日志只进内存，不落盘（`log.dart:45`）。
8. **`lib/foundation/` 反向 import 了 `lib/pages/`**（`lib/foundation/comic_source/comic_source.dart:15-16` 引了两个页面）。新代码别照抄这个方向；但也别为了"纯净分层"发起大重构。
9. **改 `ComicSource` 构造函数会连坐 `test/support/source_fixture.dart`**——它用 35 个位置参数构造。加字段请加可选具名参数，否则这里全红。
10. **版本号四处必须一致**：`pubspec.yaml:5`、`lib/foundation/app.dart:18`、`doc/release-X.Y.Z.md` 首行、git tag。核验：`RELEASE_TAG=vX.Y.Z python3 tool/check_version.py`（`doc/release-policy.md:8`）。
